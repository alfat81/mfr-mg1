# Деплой через GitHub Desktop — пошаговое руководство

Этот архив содержит **готовую к деплою статическую сборку сайта**. Не нужно
ничего собирать — достаточно запушить файлы в репозиторий через GitHub Desktop
и включить GitHub Pages.

## Содержимое архива

```
mfr-mg-github-desktop/
├── gh-pages/                  ← Готовая статика для деплоя (главная папка!)
│   ├── index.html             ← Главная страница
│   ├── 404.html               ← Страница 404
│   ├── _next/                 ← JS/CSS бандлы Next.js
│   ├── admin/                 ← Страница админки
│   ├── data/                  ← JSON-данные (документы, комиссии)
│   ├── documents/             ← PDF-файлы
│   ├── images/                ← Изображения
│   ├── .nojekyll              ← Отключает Jekyll на GitHub Pages
│   ├── CNAME                  ← Кастомный домен (mfr-mg.ru) — можно удалить
│   └── api/                   ← Статический JSON-ответ
│
├── source/                    ← Исходный код (для будущих доработок)
│   └── ...                    ← Next.js проект
│
├── GITHUB-DESKTOP-GUIDE.md    ← Этот файл
└── README.md                  ← Общая информация о проекте
```

---

## Шаг 1. Установите GitHub Desktop

Если ещё не установлен — скачайте с https://desktop.github.com/ (Windows/macOS).
Для Linux используйте альтернативу: https://github.com/shiftkey/desktop

После установки войдите в свой аккаунт GitHub.

---

## Шаг 2. Создайте репозиторий на GitHub

1. Откройте https://github.com/new
2. **Repository name:** `mfr-mg.ru` (или любое другое имя)
3. **Description:** «Кубок России по ФУМ 2026 — официальный сайт МФР»
4. **Visibility:** Public (GitHub Pages бесплатный только для публичных репо)
5. **НЕ** ставьте галочки «Add a README» / «.gitignore» / «license» — пустой репозиторий
6. Нажмите **Create repository**

GitHub покажёт страницу с инструкцией — ничего там не делайте, закройте вкладку.

---

## Шаг 3. Клонируйте пустой репозиторий через GitHub Desktop

1. В GitHub Desktop: **File → Clone repository...**
2. Вкладка **GitHub.com** → найдите ваш `mfr-mg.ru` → выберите его
3. **Local path:** выберите удобную папку (например, `C:\Projects\mfr-mg.ru`)
4. Нажмите **Clone**

GitHub Desktop создаст пустую папку с скрытой `.git/` внутри.

---

## Шаг 4. Скопируйте файлы сборки

1. Откройте папку с клонированным репозиторием в проводнике
   (в GitHub Desktop: **Repository → Show in Explorer** / **Reveal in Finder**)
2. Распакуйте этот архив
3. Скопируйте **ВСЁ содержимое папки `gh-pages/`** в папку репозитория
   (включая файлы `.nojekyll` и `CNAME` — они скрытые, включите отображение скрытых файлов)

**Важно:** файлы должны лежать **прямо в корне репозитория**, не в подпапке!
Структура должна быть такой:

```
mfr-mg.ru/                    ← корень репозитория
├── .git/                     ← создан GitHub Desktop
├── .nojekyll                 ← ✓ скопирован
├── CNAME                     ← ✓ скопирован
├── index.html                ← ✓ скопирован
├── _next/                    ← ✓ скопирован
├── admin/
├── data/
├── documents/
├── images/
└── ...
```

---

## Шаг 5. Сделайте первый коммит

1. Вернитесь в GitHub Desktop
2. Слева внизу в поле **Summary** напишите: `Initial commit: MFR FUM website`
3. (Опционально) в **Description**: `Кубок России по фигурному управлению мотоциклом 2026`
4. Нажмите кнопку **Commit to main** (или **Commit to master**)

---

## Шаг 6. Запушьте на GitHub

1. Нажмите кнопку **Push origin** (синяя, вверху)
2. Дождитесь окончания загрузки (статус внизу: "Last sync just now")

---

## Шаг 7. Включите GitHub Pages

1. Откройте ваш репозиторий на GitHub в браузере
2. **Settings** → слева **Pages**
3. В разделе **Build and deployment → Source** выберите **Deploy from a branch**
4. В разделе **Branch**:
   - Выберите ветку `main` (или `master`)
   - Folder: `/ (root)`
   - Нажмите **Save**
5. Подождите 1–5 минут — наверху появится зелёная плашка:
   «Your site is live at https://ВАШ-ЛОГИН.github.io/mfr-mg.ru/»

---

## Шаг 8 (опционально). Кастомный домен mfr-mg.ru

В архиве уже есть файл `CNAME` с содержимым `mfr-mg.ru`. Если домен другой:

1. Откройте файл `CNAME` в текстовом редакторе
2. Замените `mfr-mg.ru` на ваш домен (например, `fum.mfr.ru`)
3. Закоммитьте и запушьте изменение

**Настройка DNS** (на стороне регистратора домена):

- Если домен **корневой** (например, `mfr-mg.ru`): добавьте A-записи на IP GitHub Pages:
  ```
  185.199.108.153
  185.199.109.153
  185.199.110.153
  185.199.111.153
  ```
- Если **поддомен** (например, `fum.mfr.ru`): добавьте CNAME-запись:
  ```
  fum.mfr.ru → ВАШ-ЛОГИН.github.io
  ```

После настройки DNS:
1. Подождите 15–60 минут для распространения DNS
2. В GitHub: **Settings → Pages → Custom domain** → введите домен → **Save**
3. Поставьте галочку **Enforce HTTPS**

## Шаг 9. Проверьте сайт

Откройте в браузере:
- `https://ВАШ-ЛОГИН.github.io/mfr-mg.ru/` — для поддомена github.io
- `https://mfr-mg.ru/` — для кастомного домена (после настройки DNS)

Сайт должен открыться с главной страницей, на которой виден hero с таймером
обратного отсчёта до следующего этапа.

---

## Шаг 10. Доступ к админ-панели

1. Откройте `https://ВАШ-ДОМЕН/admin`
2. Нажмите «Войти по паролю»
3. Введите пароль: `mfr-fum-2026` (по умолчанию)
4. В форме входа в GitHub введите:
   - **GitHub Personal Access Token** — создайте на
     https://github.com/settings/tokens/new?scopes=repo (права `repo` или `public_repo`)
   - **Владелец** — ваш логин GitHub
   - **Репозиторий** — `mfr-mg.ru` (или имя вашего репо)
   - **Ветка** — `main` (или `master`)

После входа можно:
- Загружать PDF-документы (до 1 МБ каждый)
- Добавлять/редактировать/удалять региональные комиссии

Изменения коммитятся в репозиторий через GitHub API. После коммита:
1. **В GitHub Desktop** нажмите **Fetch origin** → **Pull origin** чтобы получить
   изменения локально
2. GitHub Pages автоматически пересоберёт сайт (1–2 минуты)

---

## Шаг 11. Смена пароля админки (обязательно перед деплоем!)

По умолчанию пароль `mfr-fum-2026` — это небезопасно. Смените его:

### Вариант A: если используете исходники (рекомендуется)

1. Распакуйте папку `source/` из архива в отдельное место
2. Установите зависимости: `bun install` (или `npm install`)
3. Сгенерируйте новый хеш пароля:
   ```bash
   printf '%s' 'ваш-новый-пароль' | sha256sum
   ```
4. Откройте `source/src/app/admin/page.tsx` в редакторе
5. Найдите `ADMIN_PASSWORD_HASH =` и замените значение на новый хеш
6. Пересоберите статейку: `bun run build:github`
7. Скопируйте содержимое `out/` в ваш репозиторий (Шаг 4)
8. Закоммитьте и запушьте

### Вариант B: через админку после деплоя

К сожалению, пароль зашит в собранной статике, поэтому его нельзя сменить
через админку — только пересборкой. Используйте Вариант A.

## Возможные проблемы

### ❌ Сайт показывает 404

- Проверьте **Settings → Pages → Branch**: выбрана `main/(root)`
- Подождите до 10 минут после первого пуши
- Проверьте, что файл `index.html` в корне репозитория (не в подпапке)

### ❌ Сайт открывается, но без стилей (голый HTML)

- Проверьте, что папка `_next/` скопирована в корень репозитория
- Проверьте, что файл `.nojekyll` скопирован (он скрытый!)
- Если репозиторий не на корневом домене github.io — нужно пересобрать с `basePath`
  (используйте папку `source/` и инструкцию в README.md)

### ❌ Изображения не загружаются

- Проверьте, что папка `images/` скопирована в корень
- Пути к изображениям должны быть `/images/file.webp`

### ❌ Кастомный домен не работает

- DNS-запись корректна? Проверьте: `dig mfr-mg.ru` или `nslookup mfr-mg.ru`
- В **Settings → Pages → Custom domain** введён домен?
- Подождите до 24 часов для полного распространения DNS

### ❌ Админка не сохраняет изменения

- Токен GitHub имеет права `repo`? (проверьте на https://github.com/settings/tokens)
- Ветка указана правильно? (обычно `main`)
- Репозиторий публичный? Если приватный — Pages не работает без подписки Pro

### ❌ Файл CNAME не виден в проводнике

Файлы без имени (только расширение) скрыты в Windows/macOS по умолчанию:
- **Windows:** Вид → Показать → Скрытые элементы
- **macOS:** Cmd+Shift+. в Finder

## Обновление сайта в будущем

### Через админку (для документов и комиссий)

1. Откройте `/admin` → введите пароль → введите GitHub PAT
2. Добавьте/отредактируйте документы или региональные комиссии
3. Изменения автоматически запушатся в репозиторий через GitHub API
4. В GitHub Desktop: **Fetch origin** → **Pull origin** — получите изменения локально

### Через GitHub Desktop (для контента страниц)

Если нужно изменить тексты на страницах, секции, дизайн:

1. Используйте папку `source/` из архива
2. Установите зависимости: `bun install`
3. Отредактируйте файлы в `src/`
4. Пересоберите: `bun run build:github`
5. Скопируйте содержимое `out/` в папку репозитория (поверх старых файлов)
6. В GitHub Desktop: коммит → пуш

## Структура данных сайта

Сайт загружает контент динамически из JSON-файлов:

- `/data/documents.json` — список документов (управляется через админку)
- `/data/regional-commissions.json` — реестр региональных комиссий (управляется через админку)

После изменения этих файлов через админку — сайт автоматически подхватит
обновления после пересборки GitHub Pages (1–2 минуты).
